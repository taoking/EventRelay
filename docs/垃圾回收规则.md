# 垃圾回收规则（代码库持续治理）

## 目标

持续减少 Agent 高频开发产生的代码熵、架构漂移、重复实现、过时文档和无来源技术债。

## 第一优先级：机械规则

能由 Pint、PHPStan、Deptrac、Tests、CI 确定判断的问题，不交给 GC Agent 主观判断。

## Weekly GC Agent 重点检查

1. 重复实现、重复 Helper、重复策略。
2. 文件/类/函数持续膨胀。
3. 架构绕行与模式漂移。
4. 无效抽象、过度封装。
5. 无引用/废弃代码。
6. 临时方案与长期未处理 TODO。
7. 不一致的错误处理。
8. 文档与真实代码不一致。
9. 测试重复、脆弱或明显缺口。
10. 不必要/重复/废弃依赖。

## 默认行为

Phase 0 / 初期 GC Agent 为**只读**：

- 允许读仓库。
- 允许输出报告。
- 不允许直接修改代码。
- 不允许直接 push main。
- 不允许自动 merge。

运行若稳定，再逐步升级：

1. Level 1：只报告。
2. Level 2：允许创建 Tech Debt Issue。
3. Level 3：低风险、行为保持型问题允许创建 Cleanup PR。
4. Level 4：极低风险且 CI 全绿时，才讨论自动合并。

## 自动修复禁区

以下问题只报告/建 Issue，不自动修：

- 数据库 Schema
- 用户数据
- 权限与安全策略
- 公开 API
- 核心架构边界
- 跨模块大重构
- 产品行为改变

## Cleanup PR 原则

- 一次只解决一个问题。
- 小、频繁、可回滚、可测试。
- 默认不改变业务行为。
- 优先减少重复和复杂度，不新增“大而全”抽象。
