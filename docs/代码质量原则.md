# 代码质量原则

## 基本原则

1. 优先清晰，不追求炫技。
2. 优先复用已有权威实现，避免重复 Helper。
3. 一个类/函数只承担清晰职责。
4. 默认减少复杂度，不为了“抽象”而抽象。
5. 错误必须被明确处理，不无理由吞异常。
6. 不硬编码个人路径、密钥、环境相关值。
7. TODO 必须说明原因，长期 TODO 应关联 Issue。
8. 不使用“临时修复”掩盖业务错误。

## 机械检查优先

以下类型尽量交给工具：

- 格式：Pint
- 静态问题：PHPStan/Larastan
- 依赖方向：Deptrac
- 功能回归：Tests
- Secrets：CI/仓库检查

## Agent 禁止行为

- 删除/弱化测试让 CI 变绿。
- 大面积加入 ignore/baseline 来隐藏问题。
- 为完成 Issue 修改验收标准。
- 顺手重构与 Issue 无关的大块代码。
- 新增重复实现却不先搜索仓库。
